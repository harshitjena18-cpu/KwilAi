## 2024-03-24 - DoS via Parameter Type Confusion in Express Query Parser
**Vulnerability:** The `getSuggestions` endpoint crashed when `ingredients` query parameter was passed as an object (e.g., `?ingredients[foo]=bar`). The code assumed `ingredients` was a string or array of strings, but `express` query parser (via `qs`) parses `ingredients[foo]=bar` as `{ ingredients: { foo: 'bar' } }`. This caused `ingredients.split(',')` to throw `TypeError: ingredients.split is not a function`, leading to a 500 error and potential DoS if abused.
**Learning:** Express `req.query` parsing is flexible and can return Objects where Strings are expected. `mongoSanitize` middleware only removes `$` and `.` keys but does not validate types. Input validation libraries like `express-validator` are essential not just for data format, but for strict type enforcement to prevent Type Confusion attacks.
**Prevention:** Always validate the TYPE of input parameters before using them. Use `express-validator`'s `isString()` or custom validators to ensure query parameters are of the expected type.

## 2024-07-13 - Secure cookie deletion on logout
**Vulnerability:** When a user logs out, the authentication token cookie is cleared using `res.cookie('token', 'none', { expires: new Date(Date.now() + 10 * 1000), httpOnly: true });`. However, this deletion misses the `secure` and `sameSite` flags used during cookie creation (`secure: process.env.NODE_ENV === 'production', sameSite: 'strict'`). This means that in production (over HTTPS), the browser might not delete the cookie correctly if the deletion attempt is deemed insecure or mismatched against creation policies.
**Learning:** In Express, when clearing a cookie, you must provide options that match the creation options (specifically `secure` and `sameSite`) or use `res.clearCookie('token', options)` to guarantee proper deletion across all browser security models. Mismatched options can leave valid authentication cookies lingering in the client's browser, leading to session fixation or account takeover risks on shared machines.
**Prevention:** Always mirror the cookie creation configuration when clearing/overwriting auth cookies. Ensure `secure` and `sameSite` match what was defined in the `sendTokenResponse` utility.
