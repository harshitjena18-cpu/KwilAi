## 2024-03-24 - DoS via Parameter Type Confusion in Express Query Parser
**Vulnerability:** The `getSuggestions` endpoint crashed when `ingredients` query parameter was passed as an object (e.g., `?ingredients[foo]=bar`). The code assumed `ingredients` was a string or array of strings, but `express` query parser (via `qs`) parses `ingredients[foo]=bar` as `{ ingredients: { foo: 'bar' } }`. This caused `ingredients.split(',')` to throw `TypeError: ingredients.split is not a function`, leading to a 500 error and potential DoS if abused.
**Learning:** Express `req.query` parsing is flexible and can return Objects where Strings are expected. `mongoSanitize` middleware only removes `$` and `.` keys but does not validate types. Input validation libraries like `express-validator` are essential not just for data format, but for strict type enforcement to prevent Type Confusion attacks.
**Prevention:** Always validate the TYPE of input parameters before using them. Use `express-validator`'s `isString()` or custom validators to ensure query parameters are of the expected type.
## 2024-05-04 - Unimported rate limiter causes ReferenceError DoS on Registration
**Vulnerability:** The `/register` endpoint was configured to use `registerLimiter`, but the middleware was neither defined nor imported. This resulted in a `ReferenceError` when the route file was loaded, effectively crashing or preventing the registration route from initializing and causing a Denial of Service (DoS) for new user signups. Furthermore, because the ESM `import()` syntax fails silently in the Jest test runner due to how routes are lazily loaded in Express (without full endpoint hit coverage), tests passed despite the critical error.
**Learning:** Missing definitions or imports in Express route definitions, especially those utilizing ES Modules (ESM), will cause a runtime `ReferenceError` that takes down the affected endpoints. It also highlights that `pnpm test` does not inherently catch route-level import errors if the endpoints are not actively exercised in the tests.
**Prevention:** Ensure that all middleware used in route definitions is properly defined and imported. Verify that the test suite actually exercises the routing file directly or that integration tests hit the endpoints to validate route registration.
