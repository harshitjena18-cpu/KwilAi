## 2024-03-24 - DoS via Parameter Type Confusion in Express Query Parser
**Vulnerability:** The `getSuggestions` endpoint crashed when `ingredients` query parameter was passed as an object (e.g., `?ingredients[foo]=bar`). The code assumed `ingredients` was a string or array of strings, but `express` query parser (via `qs`) parses `ingredients[foo]=bar` as `{ ingredients: { foo: 'bar' } }`. This caused `ingredients.split(',')` to throw `TypeError: ingredients.split is not a function`, leading to a 500 error and potential DoS if abused.
**Learning:** Express `req.query` parsing is flexible and can return Objects where Strings are expected. `mongoSanitize` middleware only removes `$` and `.` keys but does not validate types. Input validation libraries like `express-validator` are essential not just for data format, but for strict type enforcement to prevent Type Confusion attacks.
**Prevention:** Always validate the TYPE of input parameters before using them. Use `express-validator`'s `isString()` or custom validators to ensure query parameters are of the expected type.
## 2026-05-07 - User Enumeration and Broken Rate Limiting in Registration
**Vulnerability:** The registration endpoint leaked whether an email was already registered, enabling User Enumeration. Additionally, the route crashed due to a missing `registerLimiter` import.
**Learning:** Security measures like rate limiting can inadvertently cause outages if not properly imported. Generic error messages must be used for both manual checks and global error handlers to prevent enumeration.
**Prevention:** Ensure rate limiter middlewares are correctly defined and imported. Always return consistent, generic messages for account creation and login failures.
## 2026-05-07 - Code Review Hallucinations and Redundant Enumeration Prevention
**Vulnerability:** Code review claimed `registerLimiter` was unused despite being explicitly passed to the router in `authRoutes.js`. Furthermore, modifying the global `errorHandler.js` to mask email duplicates created a regression for profile updates.
**Learning:** The registration controller (`authController.js`) already mitigates user enumeration by checking `User.findByEmail()` explicitly before attempting creation. Adding a generic message to the global Mongoose `11000` handler was unnecessary and broke normal application behavior. Additionally, automated reviewers may flag false positives for unused middlewares.
**Prevention:** Verify code review claims manually using `grep` before attempting fixes. Trace the request lifecycle to see if a vulnerability is already handled further up the stack before adding overlapping, regression-prone generic handlers.
