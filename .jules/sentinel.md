## 2024-03-24 - DoS via Parameter Type Confusion in Express Query Parser
**Vulnerability:** The `getSuggestions` endpoint crashed when `ingredients` query parameter was passed as an object (e.g., `?ingredients[foo]=bar`). The code assumed `ingredients` was a string or array of strings, but `express` query parser (via `qs`) parses `ingredients[foo]=bar` as `{ ingredients: { foo: 'bar' } }`. This caused `ingredients.split(',')` to throw `TypeError: ingredients.split is not a function`, leading to a 500 error and potential DoS if abused.
**Learning:** Express `req.query` parsing is flexible and can return Objects where Strings are expected. `mongoSanitize` middleware only removes `$` and `.` keys but does not validate types. Input validation libraries like `express-validator` are essential not just for data format, but for strict type enforcement to prevent Type Confusion attacks.
**Prevention:** Always validate the TYPE of input parameters before using them. Use `express-validator`'s `isString()` or custom validators to ensure query parameters are of the expected type.

## 2024-03-24 - Insecure Cookie Deletion via Mismatched Options
**Vulnerability:** The logout endpoint was clearing the auth token cookie with only `httpOnly: true`, while the cookie was originally set with `secure: true` (in production) and `sameSite: 'strict'`. According to HTTP standards, to successfully clear a cookie, the `path`, `domain`, and `secure` attributes must match the ones used when the cookie was created.
**Learning:** If a cookie is set as Secure, the client will ignore instructions to delete it over HTTP unless the delete command also specifies Secure. While the Express res.cookie API might sometimes handle this gracefully depending on the exact version and setup, relying on default mismatching options can leave sensitive authentication cookies active on the user's browser after they believe they've logged out, especially in strict browser environments or behind proxies.
**Prevention:** When clearing a cookie (e.g., using `res.cookie(name, '', options)` or `res.clearCookie()`), always mirror the exact options (like `secure` and `sameSite`) that were used when creating it.
