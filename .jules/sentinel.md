## 2024-03-24 - DoS via Parameter Type Confusion in Express Query Parser
**Vulnerability:** The `getSuggestions` endpoint crashed when `ingredients` query parameter was passed as an object (e.g., `?ingredients[foo]=bar`). The code assumed `ingredients` was a string or array of strings, but `express` query parser (via `qs`) parses `ingredients[foo]=bar` as `{ ingredients: { foo: 'bar' } }`. This caused `ingredients.split(',')` to throw `TypeError: ingredients.split is not a function`, leading to a 500 error and potential DoS if abused.
**Learning:** Express `req.query` parsing is flexible and can return Objects where Strings are expected. `mongoSanitize` middleware only removes `$` and `.` keys but does not validate types. Input validation libraries like `express-validator` are essential not just for data format, but for strict type enforcement to prevent Type Confusion attacks.
**Prevention:** Always validate the TYPE of input parameters before using them. Use `express-validator`'s `isString()` or custom validators to ensure query parameters are of the expected type.

## 2024-04-10 - ReDoS and NoSQL Injection via Unsanitized Regex in MongoDB Queries
**Vulnerability:** The application was vulnerable to Regular Expression Denial of Service (ReDoS) and potential NoSQL Injection because user-provided search terms were passed directly into MongoDB `$regex` operators (in `Pantry.js`) and `new RegExp()` constructors (in `Recipe.js`) without sanitization. An attacker could provide a malicious regex string that takes exponential time to evaluate, causing the database or Node.js process to hang and resulting in Denial of Service.
**Learning:** Even when using middleware like `express-mongo-sanitize` (which only prevents basic object-based NoSQL injection by removing `$` and `.` keys), string inputs used in regular expressions must still be manually sanitized. Any user input that forms part of a regex pattern must be escaped.
**Prevention:** Always use a utility function like `escapeRegExp` (which replaces special regex characters with their escaped counterparts) on user input before passing it to MongoDB `$regex` queries or `new RegExp()` constructors. Ensure the utility function also includes a type check to handle non-string inputs safely.
